> **Scores below are the same scores published in the [Executive Summary](../EXECUTIVE_SUMMARY.md#maturity)** — this document is their full justification, not a re-scoring. A 0–5 scale is used throughout: **0** nothing exists, **1** present but not usable beyond a toy case, **2** works with significant caveats, **3** solid with known gaps, **4** strong with minor gaps, **5** no known gap. No category scores 5.

## Scores

| Category | Score | Justification |
|---|---|---|
| **Architecture** | **4** | An explicit, audited state machine ([`pipeline/runner.py`](../03_Architecture/LLD.md)); a single shared correctness definition for extractions and heal previews ([`contracts/engine.py`](../03_Architecture/HLD.md)); a Protocol seam that makes the vendor and the LLM both swappable without touching pipeline logic ([ADR-004](../03_Architecture/ADRs/README.md#adr-004--protocol-seam-for-bright-data-with-a-faithful-replay-implementation), [ADR-006](../03_Architecture/ADRs/README.md#adr-006--llm-confined-to-prose-behind-a-protocol-defaulting-off)). Not a 5: two decisions are unjustified constants ([ADR-007](../03_Architecture/ADRs/README.md#adr-007--three-band-confidence-policy-with-fixed-thresholds)), and one data store is genuinely inconsistent — the `contracts` table is written but never read as truth ([ADR-003](../03_Architecture/ADRs/README.md#adr-003--contracts-as-yaml-files-not-database-rows)). |
| **Code quality** | **4** | `ruff` clean across the engine; typed domain models throughout (`domain.py`, Pydantic); no dead abstractions in the hot path. Not a 5: `errors.py` defines a careful typed error taxonomy the pipeline does not use, raising bare `ValueError` instead ([Gap Report G-07](Engineering_Gap_Report.md#ranked-gaps)) — a real inconsistency between documented intent and implementation. |
| **Testing (backend)** | **4** | 23 tests, covering all four contract gates, all five drift classes, the full heal→verify→approve/reject/review lifecycle, and one full HTTP-level end-to-end run ([Test Strategy](../07_Testing/Test_Strategy.md)). Not a 5: API coverage is 3 of 19 routes — every state-changing endpoint is untested at the HTTP layer ([Gap Report G-11](Engineering_Gap_Report.md#ranked-gaps)) — and the three reliability handlers are never exercised by inducing the failures they claim to survive ([Gap Report G-02](Engineering_Gap_Report.md#g-02--reliability-handlers-never-exercised)). |
| **Testing (frontend)** | **0** | Zero tests against 581 lines of hand-written DOM construction in `frontend/assets/app.js` ([ADR-011](../03_Architecture/ADRs/README.md#adr-011--zero-build-vanilla-es-module-frontend)). The UI *is* the demo — this is the least-tested surface with the most judge-facing exposure. |
| **Reliability** | **3** | Real isolation exists: alert delivery failure doesn't fail the pipeline, a scheduler tick's exception doesn't stop the scheduler, LLM failure falls back structurally to deterministic prose ([Reliability & Failure Design](../10_Operations/Reliability_and_Failure_Design.md)). Not higher: none of the three is validated by a failure-injection test, there is no retry/backoff on any external call, and no process supervision exists — the whole system dies with one process crash. |
| **Observability** | **3** | The audit ledger is a genuine strength — every machine and human decision is queryable application data, not a log file ([Observability § 1](../10_Operations/Observability.md#1-what-exists-the-audit-ledger)). Not higher: no structured logging, no metrics endpoint, no tracing, no health/readiness endpoint, and the one headline stat (`heal_mttr_seconds`) silently mixes seeded and measured data ([Observability § 4](../10_Operations/Observability.md#4-blind-spots-this-creates)). |
| **Performance** | **3** | What is measured is measured honestly and passes its own (post-hoc) targets with real margin: contract evaluation p95 0.20 ms, no-change run p95 7.62 ms, heal cycle p95 14.55 ms ([Performance Validation](../07_Testing/Performance_Validation.md)). Not higher: every number is replay-mode only, on one machine, single-threaded — live-mode latency, the number that would actually matter in production, has never been measured because no live call has succeeded. |
| **Security** | **2** (was 1, revised 2026-08-22) | No shell injection (list-form subprocess argv, [ADR-005](../03_Architecture/ADRs/README.md#adr-005--wrap-the-official-cli-rather-than-calling-rest)), no SQL injection (parameterised queries throughout, `db.py`), secrets correctly kept out of git, and — as of 2026-08-22 — a real, tested bearer-token authentication gate plus a `127.0.0.1` default bind ([Security Architecture](../06_Security/Security_Architecture.md)). The bump from 1 reflects that authentication now genuinely *works*, not just that it exists in a toy form: verified 401 with no/wrong token, 200 with a correct one. Not higher: it is **opt-in**, off by default; there is still no authorisation/RBAC layer (an authenticated caller can do anything any other authenticated caller can), no rate limiting, no CSRF protection, no security headers, no TLS. |
| **Deployment** | **1** | Runs reliably and reproducibly *for its intended scope* — `pip install -r requirements.txt && python3 backend/serve.py` genuinely works with no hidden dependency ([Deployment Architecture § 8](../08_Deployment/Deployment_Architecture.md#8-running-it-today)). Scored **1**, not 0, for that reproducibility. Everything beyond single-machine, single-process, dev-server deployment is absent: no container, no WSGI server, no process supervisor, no reverse proxy, no TLS, no environment separation ([Deployment Architecture](../08_Deployment/Deployment_Architecture.md)). |
| **Documentation** | **4** | This documentation set itself — evidence-cited, status-labelled, internally cross-referenced, and willing to state "this claim is false as written" about its own error-handling docstring ([API Error Catalog](../05_API/API_Error_Catalog.md)). Not a 5: it documents a system, it does not replace the missing OpenAPI specification ([GAP-17](../02_Requirements/Requirements_Gap_Analysis.md#low)), and some judgement calls in it (e.g. gap rankings) are this review's own synthesis rather than independently reproducible facts. |
| **AI safety** | **3** | The strongest single property in the system: the `Provider` interface returns only `str`, so no pipeline decision can be influenced by the model — enforced by the type system, not by convention ([ADR-006](../03_Architecture/ADRs/README.md#adr-006--llm-confined-to-prose-behind-a-protocol-defaulting-off)). A heal's own success report is never trusted either ([`healing/verifier.py`](../09_AI_ML/AI_Architecture.md)). Not higher: prompt injection into both the heal prompt and the Anthropic prompt is unmitigated and untested ([AI Architecture § 5](../09_AI_ML/AI_Architecture.md#5-ai-safety), [Threat Model T-08](../06_Security/Threat_Model.md#t-08-in-depth--the-ai-specific-threat-that-matters)), and the vendor AI's real-world behaviour has never been observed to calibrate against ([§ Live-path validation status](../09_AI_ML/AI_Architecture.md#live-path-validation-status)). |
| **Data integrity** | **3** | Quarantine is real and validated — unverified data never reaches analytics or alerts, enforced by a `quarantined = 0` filter at the one place last-known-good is read ([`pipeline/runner.py :: _last_good`](../03_Architecture/LLD.md)). Referential integrity is enforced at the SQLite layer (`foreign_keys=ON`); write contention under the single-writer constraint now waits and retries for up to 5s (`busy_timeout=5000`, added 2026-08-22) instead of raising immediately. Not higher: no database-level enforcement of "append-only" on the audit ledger (a convention, not a constraint — [Observability § 1](../10_Operations/Observability.md#1-what-exists-the-audit-ledger)), and no backup/recovery capability at all ([Reliability & Failure Design § Disaster recovery](../10_Operations/Reliability_and_Failure_Design.md#disaster-recovery)). |

## Classification

Four rungs, each requiring the one below it plus its own bar:

| Rung | Bar | Met? |
|---|---|---|
| **Hackathon Ready** | Runs reproducibly for a judge, on demand, offline, with a scripted demo | **Yes** — [`DEMO.md`](../../DEMO.md), [Risk Register R-24/R-25](../06_Security/Risk_Register.md) |
| **Demo Ready** | The above, plus: every claim made in the demo is backed by a test or an explicit label, and the system survives the intended demo's exact failure scenarios (scripted, not arbitrary) | **Yes** — 23 tests back the pipeline claims; the demo's break/heal/semantic-catch beats are each backed by a named test |
| **Beta Ready** | The above, plus: authentication *required* (not merely available), deployable to a real (even if small) user base, with basic reliability validated by failure-injection, and a real vendor integration proven to work at least once | **No** — blocked on making auth mandatory, Deployment (1), and the live-path validation gap |
| **Production Ready** | The above, plus: horizontally scalable or explicitly scoped as single-instance with documented limits, monitored, backed up, with an on-call-usable observability surface | **No** — not attempted at this stage, correctly so for a 7-day build |

**Classification: Demo Ready.** Not Beta Ready and not Production Ready — and the reasons are specific and short, not a vague "needs more polish": **authentication is opt-in, not mandatory** (Security = 2, up from 1 on 2026-08-22 — the mechanism exists and works, but the default posture is unchanged), **deployment packaging** (Deployment = 1), and **live-path validation** (the one unmet objective, [Project Vision § OBJ-9](../01_Product/Project_Vision.md)). None of the three blockers is an architecture problem — Architecture scores 4, the highest tier below Documentation. This is a meaningfully different diagnosis than "the system isn't ready because it's poorly engineered"; it is ready in the dimension that is hardest to fix quickly (design) and not ready in the dimensions that are comparatively cheap to fix (auth is now built, just not mandatory; containerisation: ~2 hours) or outside engineering's control (vendor account access).

Remaining: make `DW_API_TOKEN` mandatory outside `127.0.0.1`, and add an authorisation layer | ~1 h done; ~1 h more to require it — [Gap Report G-01](Engineering_Gap_Report.md#g-01--no-authentication-on-any-endpoint) |
| Deployment = 1 | Containerise; replace the Flask dev server with a WSGI server | ~2–3 h — [Deployment Architecture § 9](../08_Deployment/Deployment_Architecture.md#9-recommended--production-deployment-shape) |
| Live-path validation | One successful `scraper create` → `heal` → `approve` transcript | Blocked on vendor account provisioning, not code — [AI Architecture § Live-path validation status](../09_AI_ML/AI_Architecture.md#live-path-validation-status) |

Closing the first two does not require new architecture — both are additive changes to an already-sound design, which is the practical meaning of an Architecture score of 4 sitting next to a Security/Deployment score of 1.
